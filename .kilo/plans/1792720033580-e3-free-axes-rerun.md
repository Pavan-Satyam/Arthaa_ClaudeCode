## Step 2 — Pre-registered XGBoost over the factor zoo (architecture doc's own recipe)

Recipe anchor: `arthaai-architecture.html:250` — "Alpha factors → tabular model (XGBoost) →
signal → backtest gate → (only if it wins) → live use."

### 2a. Dependency
- Add an optional extra (e.g. `ml = ["xgboost>=2.0", "scikit-learn>=1.4"]`) to `pyproject.toml`.
  Install into `.venv`. Keep optional so the core package and DB-independent suite don't require it.

### 2b. Harness (net-new) — with the three review fixes baked in
Build `arthaai/factors/xgb_signal.py` producing a per-symbol, per-date signal series in the shape
`_signal_map_for` expects, plugging into the unchanged `promote-sweep` gate. The three design rules
from the review (all pre-registered before running):

- **Target (review fix 2-i):** **volatility-adjusted forward return** = raw n-day forward return ÷
  trailing 20-day realized vol, **not** raw forward return. Rationale: the 73-symbol universe mixes
  high-beta tech equities with low-vol commodity ETFs (GLD) and energy names; a pooled model on raw
  fwd returns learns to predict high-vol regimes, not edge. Add an **asset-class categorical feature**
  (equity vs commodity-ETF) rather than training fully separate models (one model, same discipline).
- **Features (review fix 2-ii):** **pure backward-looking rolling factors only** — the qlib158
  beta/corr/cord windows (5/10/20/30/60) + raw `tsmom`/`xsmom` values + the asset-class categorical.
  **Exclude `ic_composite` and any composite/meta-signal as a feature.** Reason: `ic_weighted_composite`
  (composite.py:102-176) computes an *expanding* IC over the whole loaded panel; reusing its per-date
  output as a feature leaks across the walk-forward boundary. Backward-looking factors only.
- **Position mapping (review fix 2-iii):** **EMA smoothing + hysteresis**, not a naive `predict()>0`
  threshold. Pre-register: smooth the raw score with a 5-day EMA; **enter long** when the smoothed score
  exceeds the 60th percentile of the *in-sample* window; **exit only** when it drops below the 40th.
  Rationale: a daily binary threshold churns positions and bleeds the 10 bps round-trip cost; the E3
  gate is long-only > B&H with MaxDD ≤ 20%, so turnover control is load-bearing.

Walk-forward: **expanding-window** fit on in-sample, predict into the next OOS window. **No tuning on
any OOS window** — all hyperparameters (max_depth, n_estimators, learning_rate, subsample,
colsample_bytree, reg_alpha/reg_lambda) frozen in the §3 pre-registration before the run.

### 2c. Pre-register before running
Add family 9 (`xgb_zoo`) to `E3_EVALUATION_PROTOCOL.md §3` **before** the run: state the feature set,

### 2d. Wire + run + record

- Run on the frozen 73-symbol sample, `--limit 3100 --cost-bps 10 --no-save` (1a.5 audit first).

## Step 3 — Free exogenous axes, sequenced by universe (with PIT effective-date alignment)

Each axis = a free, PIT, enterprise-licensable source → a per-symbol signal map → a pre-registered
E3 variant on the frozen sample. **Every adapter must compute an `effective_date`** (the date the
data became *publicly tradeable*, i.e. after the publication/release lag) **and align to OHLCV via
`merge_asof(direction="backward")`** — the same PIT discipline `pit_latest` uses
(fundamentals_pit.py:99-104). Joining on a dataset's native reference/period date is a look-ahead.

### Phase A — commodities / energy (CFTC COT + EIA)
- **CFTC Commitments of Traders** (free since 1995; weekly): speculator vs commercial positioning.
  New `arthaai/data/cftc.py`. **PIT:** records are keyed by Tuesday *report* date but released Friday
  3:30pm ET — `effective_date = report_tuesday + 3 business days` (visible for Friday close / Monday
  open). Signal map for **GLD, SLV, USO, DBC**. Pre-register the construction (net non-commercial
  positioning z-score / Δ) before running.
- **EIA weekly petroleum (WPSR)** (free API key; Wed 10:30am release): Cushing stocks / inventories.
  Extend `arthaai/data/alternative.py:41` `get_eia_series`. **PIT fix:** the adapter currently maps
  `period` (the period-*ending* date) to `ts` (alternative.py:76) — a 5-day look-ahead. Change it to
  `effective_date = period_friday + 5 calendar days` (+6 on weeks with a Monday federal holiday).
  Signal map for **USO, XOM**. Needs `EIA_API_KEY` in env/Vault.

### Phase B — equities (SEC Form 4 only; FINRA moved to exploratory)
- **SEC Form 4** (free via EDGAR; filed within 2 business days): insider buy/sell. New
  `arthaai/data/form4.py` (EDGAR full-text / `submissions.zip` nightly bulk). **PIT:** align strictly on
  `acceptanceDateTime` (truncate to the next trading session if filed after 16:00 ET), **never**
  `transactionDate` (which is the transaction day, not the disclosure day). Signal map for the
  **equity subset** of the frozen universe. Pre-register (e.g. insider net-buy indicator, lagged to
  the acceptance/filing date). Full 10+ year PIT history via EDGAR bulk — this is why Form 4 carries
  Phase B instead of FINRA.
- **FINRA short interest — moved OUT of the E3 sweep (review fix 4).** Rationale: the free FINRA
  downloadable files expose only ~12–24 months rolling (web grid is anti-bot gated), and even a
  hypothetical 5y series cannot pass a 10-year every-window gate over 3,100 bars. Retain as an
  **exploratory side-note only** — not a gated variant — to be revisited if a paid/licensed feed is
  ever procured.

### Phase C — market-wide, split (review fix 5)
- **Phase C1 (immediate, run now):** **Cboe VIX + VIX3M** (free daily CSVs, clean, back to ~2007):
  implied-vol level + term-structure ratio (VIX/VIX3M) → a market-regime gate for all 73 symbols. New
  `arthaai/data/vix.py`; wire through `arthaai/factors/` consistent with the existing
  `regime`/`macro` gates. Pre-register + run on the frozen sample, `--limit 3100 --cost-bps 10 --no-save`.
- **Phase C2 (deferred — out of scope unless C1/others show edge):** **GDELT 2.0** per-entity tone.
  The free GDELT REST API has only a ~3-month rolling window; raw 15-min files are TB-scale across
  2015–2026. Full history requires **Google BigQuery `gdelt-bq.gdeltv2.gkg_partitioned` with
  partition-date + organization filters and a `maximum_bytes_billed` cap** — not a scrape and not the
  REST API. Do **not** build `arthaai/data/gdelt.py` under this plan; revisit only after C1 + the other
  free axes produce (or fail to produce) edge.

Each in-scope phase: add the signal name(s) to `_signal_map_for` + `tests/test_signal_routing.py`, add a
§3 pre-registration entry, run with `--limit 3100` on the frozen sample (1a.5 audit first), and record in
`evaluation/e3_results.md`. For any axis whose real history < 10y (e.g. VIX3M start), record the actual
horizon and flag it under the protocol's §6 limitations.

## Risks

- **DB depth (the 1a.5 gate):** a short TimescaleDB silently turns `--limit 3100` into a ~2y run with
  no error. The audit is mandatory before any sweep; if the universe is shallow, backfill to full
  history first or the whole re-run is wasted.
- **Docker/TimescaleDB availability:** all sweeps are DB-backed and hang without the stack; ensure
  `docker compose up -d` before any run.
- **Free-tier limits/terms:** EIA needs a key; GDELT/VIX3M history may start mid-2010s → real horizon
  may be < 10y for some axes (declare it under §6 limitations).
- **XGBoost OOS discipline:** the protocol forbids tuning on an OOS window; hyperparameters, target
  transform, and hysteresis thresholds must be frozen in the §3 pre-registration **before** the run,
  or the result is void and must be redone on fresh windows.
- **PIT alignment is the exogenous-axis failure mode:** joining CFTC/EIA/Form 4 on their native
  reference date (not the release date) is a 3–5 day look-ahead; the `effective_date` + `merge_asof`
  rule is what keeps these axes E3-legal.
